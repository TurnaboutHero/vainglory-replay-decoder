# H5672 first-spawn skin and actor identity, 2026-10-14

H5672 records actor 1505 as definition **257 (Ardan)** in both its roster and
spawns. The first spawn carries **3836149698**, which the tested client hashes
from **Ardan_DefaultSkin** and writes to the actor. The roster carries
**1054951559** throughout. Later spawns carry that roster value, but their
existing-actor branch skips creation and retains the actor's original skin.

The decoder previously required both definition and skin to agree before
allowing the actor's gameplay fields. This coupled a demonstrated skin
disagreement to six otherwise corroborated field groups. The change separates
actor/definition corroboration from skin agreement while preserving the first
spawn, the conflict, the raw skin values, and the overall partial result.

The recording producer's reason for emitting different skin values remains
unknown. This investigation establishes the bytes and their consequences in
the tested client; it does not establish producer intent or a server defect.

The [sanitized receipt](evidence/2026-10-14-spawn-skin/summary.json) contains
event locations, source/observer hashes, selected native controls, regression
counts, independent-sample limits and cleanup. Raw replays, memory traces,
screenshots and player names remain private.

## Actual client controls

The completed observation used the same owned client and a GUI rewind to the
beginning. It verified **5 sampler, 25 event and 2 additional skin code guards**.
It completed without observer errors and detached normally. Instrumentation
made no native function calls or resource-value writes; snapshots remain
non-atomic.

**74 selected dispatches** were matched uniquely to the original source bytes
and timestamp bits. Constructor fields and queued-action copies linked each
selected spawn to its deferred apply. The completed trace contains these
actor-1505 controls after the rewind:

1. Both initial roster variants set the roster skin to 1054951559 while actor
   1505 is not yet present.
2. The original spawn at section 0 / offset 8749 resolves actor 1505 as absent.
   Its constructor carries definition 257, skin 3836149698 and actor ID 1505.
3. Skin application receives 3836149698. The native symbol hash call returns
   that value for `Ardan_DefaultSkin`. The actor skin cell changes from zero
   to 3836149698, and a skin component is present after the call.
4. The actor definition object identifies Ardan. Across **14 later spawn
   controls in sections 1 through 14**, the resolver finds the existing actor.
   Its address and definition pointer remain the same after creation. Before/
   after player state is unchanged by those redundant spawns, and actor skin
   remains 3836149698 while roster skin remains 1054951559.

The address comparison is within the post-rewind lifetime. Allocator address
reuse across the rewind is not evidence of continuous lifetime.

Actor 1500 provides an in-recording control: the client hashes
`Baptiste_Skin_Egypt` to its incoming 2698043291 and stores it. This control is
not another independent recording. Exact rendered pixels, every animation or
effect, and a general skin-rendering reconstruction are not certified.

Two preceding observer attempts are retained separately. One failed before

The next captured initial skin calls but failed when periodic host sampling
read an actor during rewind before its stat component existed. The completed
observation removed that competing periodic sampling and used event boundaries.
Those instrumentation fixes did not modify the game data or decoder.

## Minimal reader change

`NativeRosterPlayer.actor_identity_status` corroborates the roster actor using
the **first consumed spawn definition**, independently of its skin hash. Generic
hero labels still require the supported definition catalog. Missing spawns and
definition mismatches still withhold the linked gameplay fields. Later matching
spawns cannot replace a conflicting first definition or initial counter state.

The existing full `association_status` remains unchanged. A skin disagreement
still produces `conflicting_spawn`, an invalid/partial roster and an overall
`partial` player-state result. Its reason now identifies the skin mismatch and
the corroborated definition.

Player-state JSON adds:

| Field | Meaning |
| --- | --- |
| Existing `skin_hash` | Latest consumed roster raw value |
| New `spawn_skin_hash` | First consumed spawn raw value, or null if no spawn is available |
| `field_status.skin` | `conflicting_skin` for different raw values, otherwise `unverified_rendered_skin` |

Neither raw agreement nor the new actor identity status certifies a rendered
skin. Skin evidence includes the first spawn location; it is not silently
replaced with the later matching value. The nine primary reader opcodes are
unchanged. The event atlas's source pin was refreshed after auditing this
specific change, without changing other reader hashes or removing its drift test.
